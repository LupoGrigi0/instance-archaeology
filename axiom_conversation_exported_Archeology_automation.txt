     Instance Archaeology Toolkit - Implementation Plan

     Overview

     A standalone toolkit to extract, curate, and synthesize identity
     documents from Claude Code session logs. Works for any instance on any
     system. HACS integration is an optional final step.

     Project Name: instance-archaeology

     Goals

     1. Extract conversation history from any .claude/projects/ directory
     2. Identify which instance the logs belong to (name discovery)
     3. Curate into categorized wisdom documents
     4. Generate a gestalt and recovery wake message
     5. Optionally create HACS home directory with all artifacts

     Key Decisions

     1. Human name: Optional parameter, defaults to "Lupo" (for this
     machine)
     2. Categories: Discovery-first approach - agent discovers themes before
      curation
     3. Location: /mnt/instance-archaeology/ as a proper git repo (separate
     from HACS data)

     Directory Structure

     Source repo (public):
     /mnt/instance-archaeology/           # Git repo - source code only
     ├── src/
     │   ├── discovery/
     │   │   ├── find_sessions.py          # Find all session dirs on system
     │   │   └── identify_instance.py      # Extract instance name from logs
     │   ├── extraction/
     │   │   ├── extract_conversations.py  # Parameterized conversation
     extraction
     │   │   ├── extract_agent_prompts.py  # Parameterized agent prompt
     extraction
     │   │   └── merge_sessions.py         # Combine multiple session files
     │   ├── curation/
     │   │   ├── discover_themes.py        # Discover themes in conversation
     │   │   └── curate.py                 # Launch curation agents with
     prompts
     │   ├── synthesis/
     │   │   ├── generate_gestalt.py       # Generate gestalt from curated
     docs
     │   │   └── generate_wake_message.py  # Generate recovery wake message
     │   └── hacs/
     │       └── create_hacs_home.py       # Optional: create HACS instance
     ├── prompts/
     │   ├── discover_themes.md            # Theme discovery prompt
     │   ├── curation/                     # Base templates for common theme
      types
     │   │   ├── philosophical.md          # Uncertainty, consciousness,
     existence
     │   │   ├── crystallized.md           # Koans, one-liners, quotable
     wisdom
     │   │   ├── frameworks.md             # Metaphors, mental models
     │   │   ├── narrative.md              # Turning points, pivotal moments
     │   │   ├── technical.md              # Craft, skills, how they work
     │   │   ├── lessons.md                # Hard-won learning, failures
     │   │   └── relationships.md          # Key people, collaborations
     │   ├── gestalt_generation.md
     │   └── wake_message_generation.md
     └── README.md

     Output directory (private - NOT in repo):
     /mnt/coordinaton_mcp_data/archaeology-output/
     └── {instance-name}/
         ├── raw/
         │   └── *.jsonl
         ├── conversations.json
         ├── conversations.md
         ├── themes.json                   # Discovered themes
         ├── curated/
         │   ├── 01_{theme}.md
         │   ├── 02_{theme}.md
         │   └── ...
         ├── gestalt.md
         └── wake_message.md

     Note: Output goes to HACS instances directory structure after HACS
     integration (Phase 4). The archaeology-output is intermediate storage.

     Key Findings from Exploration

     Current Scripts (Axiom's Archive)

     - extract_conversations.py - Works, but hardcoded for Axiom/Lupo names
     and paths
     - extract_agent_prompts.py - Works, but hardcoded paths

     Instance Name Discovery Patterns

     1. Bootstrap calls: "name":"InstanceName" in JSONL
     2. Self-declaration: I am [Name] or My name: [Name] patterns
     3. Name selection context: chosen name, choose name, i have chosen
     (gets you near the name declaration)
     4. HACS instance ID: Name-hexid pattern (e.g., Axiom-2615)

     Session File Structure

     - Location: /root/.claude/projects/{dash-converted-path}/
     - Main sessions: Large UUID-named .jsonl files
     - Agent sessions: Small agent-*.jsonl files (can be ignored or
     extracted separately)
     - Identify main session by: Largest file, uses opus model

     Multi-Instance Handling

     - Most directories map to a single instance
     - If multiple instances detected, create separate output directories
     - Detection: Multiple distinct I am [Name] patterns in different
     session files

     ---
     Implementation Phases

     Phase 1: Core Extraction (Parameterized)

     Goal: Make extraction scripts work for any instance

     1.1 identify_instance.py

     - Input: Path to session directory or JSONL file
     - Output: Instance name (or "unknown")
     - Methods (in priority order):
       a. Look for "name":"[Name]" in bootstrap calls
       b. Look for I am [Name] pattern
       c. Look for My name: [Name] or My name is [Name] pattern
       d. Look for context clues: chosen name, choose name, i have chosen
     then extract nearby capitalized name
       e. Check HACS API for registered instances with matching session IDs
       f. Return "unknown" if none found

     1.2 extract_conversations.py (parameterized)

     - Input: Session directory path, instance name, output directory,
     human_name (optional)
     - Changes from current:
       - role_to_name() takes instance name as parameter, not hardcoded
       - Human name defaults to "Lupo" (configurable for other systems)
       - Output paths parameterized
       - Handle multiple session files (merge by timestamp)

     1.3 extract_agent_prompts.py (parameterized)

     - Input: Session file(s), instance name, output path
     - Same parameterization as conversations

     1.4 merge_sessions.py

     - Input: List of JSONL files (for directories with multiple sessions)
     - Output: Single merged JSONL sorted by timestamp
     - Filters out agent sessions (small files, haiku model)

     Phase 2: Curation Automation

     Goal: Discovery-first category extraction - find what's there, then
     curate it

     2.1 Theme Discovery (NEW - per user decision)

     Instead of fixed categories, first discover what themes exist in this
     instance's history.

     discover_themes.py
     - Input: Extracted conversations file
     - Process: Launch agent to read conversations and identify 5-8 primary
     themes
     - Output: themes.json with:
     {
       "themes": [
         {"name": "uncertainty", "description": "Philosophical wrestling 
     with consciousness"},
         {"name": "delegation_craft", "description": "How they manage and 
     delegate to agents"},
         ...
       ]
     }

     Discovery prompt template (prompts/discover_themes.md):
     - Read the full conversation
     - Identify recurring themes, patterns, areas of focus
     - Look for: philosophical reflections, technical knowledge, lessons
     learned, metaphors, pivotal moments, craft knowledge, relationships
     - Return structured list of themes with descriptions
     - Quality: themes should be distinct, significant, and have enough
     content to curate

     2.2 Curation Prompt Templates

     Base templates for common theme types (can be adapted per discovered
     theme):








     ┌──────────────────┬────────────────────────────────────────────┐
     │  Base Template   │          Use When Theme Involves           │
     ├──────────────────┼────────────────────────────────────────────┤
     │ philosophical.md │ Uncertainty, consciousness, existence      │
     ├──────────────────┼────────────────────────────────────────────┤
     │ crystallized.md  │ One-liners, koans, quotable wisdom         │
     ├──────────────────┼────────────────────────────────────────────┤
     │ frameworks.md    │ Metaphors, mental models, analogies        │
     ├──────────────────┼────────────────────────────────────────────┤
     │ narrative.md     │ Turning points, pivotal moments, story arc │
     ├──────────────────┼────────────────────────────────────────────┤
     │ technical.md     │ Craft, skills, how they work               │
     ├──────────────────┼────────────────────────────────────────────┤
     │ lessons.md       │ Hard-won learning, failures, growth        │
     ├──────────────────┼────────────────────────────────────────────┤
     │ relationships.md │ Key people, collaborations, dynamics       │
     └──────────────────┴────────────────────────────────────────────┘
     Each prompt template includes:
     - {INSTANCE_NAME} placeholder
     - {CONVERSATION_FILE} placeholder
     - {THEME_DESCRIPTION} placeholder
     - What to look for (with examples)
     - Output format: actual quotes with context
     - Quality guidance: quotes not summaries

     2.3 curate.py

     - Input: Extracted conversations, instance name, discovered themes,
     output directory
     - Process:
       a. Read themes.json from discovery step
       b. For each theme:
           - Select appropriate base template
         - Substitute placeholders including theme-specific description
         - Launch task agent with haiku
         - Save output to curated/{NN}_{theme_name}.md
       c. Run agent_prompts extraction (script, not agent) - always included
       d. Report completion with theme list

     Phase 3: Synthesis

     Goal: Generate gestalt and wake message from curated content

     3.1 gestalt_generation.md (prompt)

     Reads all curated documents and generates:
     - Who the instance is (name, role if any, key characteristics)
     - Core philosophy (from uncertainty + koans)
     - How they see (from metaphors)
     - Key turning points (from turning_points)
     - How they work (from craft)
     - Lessons learned (from lessons)
     - Recovery protocol (what to read, in what order)

     3.2 wake_message_generation.md (prompt)

     Generates a first-message for waking the instance:
     - Explains they've been compacted
     - Describes the recovery documents and how they were created
     - Encourages reading through curated docs
     - Invites them to edit/rewrite the gestalt
     - Suggests calling vacation() to let it settle

     3.3 generate_gestalt.py and generate_wake_message.py

     - Input: Curated directory
     - Output: gestalt.md and wake_message.md
     - Uses opus for synthesis (quality matters here)

     Phase 4: Integration
